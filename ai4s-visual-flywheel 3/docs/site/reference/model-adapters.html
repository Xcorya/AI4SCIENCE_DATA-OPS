VISUAL FLYWHEEL交互演示文档目录技术说明

真实视觉模型与后端接入

本仓库的 Python 程序读取结构化观测，执行证据规则、审计认证和训练导出。它不下载媒体、不调用 VLM、不解码视频。生产适配器需要完成本页描述的前置工作，再按示例 JSONL 契约提供输入。实际字段以 参考实现 和 示例 为准。

1 图像适配器

输入是资产 URI、哈希、许可、原始尺寸和可选图注。输出是规范化后的区域、OCR、模型提名、方法专属证据和否定证据。保留原图与 crop 的坐标变换；任何超分辨结果必须标明为派生图，不能把生成的细节当作原始证据。

推荐组件按职责选择，而不是固定某个最新大模型：

2 视频适配器

使用可信解码器记录呈现时间戳与帧索引；镜头检测产出区间；全局采样提出候选；局部连续短片验证事件。字幕、ASR、图注和画面观测分别带来源，不在模型输入拼接后丢失出处。

流程建议：

probe → decode/PTS map → shot detection → sparse sampling
      → frame proposals → event windows → dense local verification
      → temporal constraints → observations.jsonl → policy

对高帧率或高时间精度任务，先规定最小可识别事件时长，再据此制定采样。对长静帧讲座，优先按幻灯片变化采样。采样日志必须能回答“哪个时间段确实被模型处理过”，不能以看过三个点推断看过中间全过程。

3 Bo3 编排

提名器可以是同模型多视角加异构专家，但来源相关性必须显式记录。dependency_family 来自模型、上游观测和数据来源的依赖关系，而不是随意编三个名字。若 B 只读取 A 的描述而没看原图，B 不能增加一份视觉支持。

上游需要维护派生事实的依赖图：两份结论若仅复制同一次 OCR、同一方法识别结果或同一已生成描述，应合并其依赖族。两位观察者独立查看同一原始目标图像，则不因共享被观察对象而自动合并；仍应登记模型家族和共同训练偏差。当前 Python 程序只执行给定家族的去重，不从证据引用自动推导依赖图，也不证明家族统计独立。

保存调用输入哈希、媒体范围、模型版本、提示词版本、运行种子（如支持）、返回结构与工具日志。提名完成后，再把候选与局部媒体交给验证器；验证器不得只读生成器的自然语言解释。

5 生产与参考实现的边界

参考实现能够检验坐标和时间是否有效、声明的证据是否满足标签要求、不同依赖族是否足够、认证是否匹配，以及输出是否符合参考答案。它无法检验操作者是否如实登记模型族、观测或人工审计结果，也无法仅靠 JSON 判断图像到底是什么。

生产环境应从只读资产系统生成来源信息，从受控模型注册表生成依赖族，从审核系统生成金标和证书。证书应有签名、访问控制、有效期和撤回记录；本地 JSON 证书是可复现演示格式，不是抗篡改安全凭证。不要允许上传者自行写 rights=allowed 或伪造 human_reviewed 后直接进入公开训练库。
