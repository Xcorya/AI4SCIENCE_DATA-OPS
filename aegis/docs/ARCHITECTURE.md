# AEGIS 设计说明

AEGIS 将输入完整性、记录质量、许可策略和决策签发分开处理。入口校验失败不会生成业务报告；合法交付但质量/许可不符会生成明确的拒收或复核报告。

## 模块

| 文件 | 职责 |
|---|---|
| `aegis/protocol.py` | 与 FORGE 相同的规范化、签名及交付校验 |
| `aegis/engine.py` | 完整记录扫描、许可规则、Wilson 统计、独立核验校验 |
| `aegis/store.py` | 原交付不覆盖、报告追加、签名与许可约束的最多 7 天有效期 |
| `aegis/httpd.py` | 同源本地 JSON API 与静态工作台 |
| `aegis/__main__.py` | 密钥及 demo fixtures 播种 |

每次 inspect 验证交付、运行全部规则、生成独立报告，再在同一个事务中保存交付/报告/事件。如果交付 ID 已存在但内容不同，拒绝整个写入。

## 质量扫描

schema 是必填字段约束：不存在、null、空字符串、纯空白字符串计入缺失；存在但实际 JSON 类型不匹配计入类型缺陷。integer/number 不接受 bool。

integer 按数学整数值判断，1 与 1.0 等价，小数不匹配；与规范化、持久化和文件传递保持一致。

记录重复定义为：整行规范化字节已出现，或非空唯一键的规范化值已出现。从第二次出现计数。唯一键缺失计入缺失，不把所有空键视为同一有效键；相同完整空行仍可触发整行重复。

质量率使用 missing、schema、duplicate 行索引集合并集，以扫描记录数作分母。一个坏行可能同时出现在多个子指标，但总体缺陷只计一次。

错误例子只保留行号和规则原因，最多 12 个，不回显原始值。此举减少报告中的敏感信息；原交付仍保存在本地数据库，state API 也返回它。

## PII 线索

检查 email、phone、ssn、passport、身份证、手机号等字段的非空值，以及字符串中的邮箱模式。若需求 `allow_pii=false`，有线索则要求复核。

它不覆盖所有个人信息、不提供脱敏处理、不验证同意记录，也不保证没有误报/漏报。PII 线索不加入契约缺陷率。

## 许可策略

| 声明 | 不明情况 | 明确不符 |
|---|---|---|
| source/license/evidence | 缺失要求复核 | 此版不查外部证据真实性 |
| rights_verified | 非 true 要求复核 | 仍需独立核验 |
| purposes/regions | 缺失/错误类型要求复核 | 不包含请求范围则拒收 |
| derivatives | 需要派生但权限不明则复核 | 需要派生而明确 false 则拒收 |
| valid_until | 缺失/无效 ISO 日期复核 | 早于 UTC 当天则拒收 |
| prohibited_source | 非明确 bool 状态要求复核 | true 则拒收 |

人工核验要求 confirmed=true、非空 reviewer、非空 evidence_note、含时区且距当前时间至多 24 小时的 reviewed_at。该声明不消除其他复核/拒收项。

## 覆盖与统计

完整交付使用实际扫描缺陷比例与阈值比较，超阈值拒收，等于阈值允许。

样本源为供应商，无法证明随机性，始终复核；Wilson 双侧 95% 上界超过阈值时追加统计证据不足说明。若声明总量小于订单数量，则无论覆盖方式均拒收。

## 决策及报告

任何 reject 项 → rejected；否则任何 review 项 → review；否则 accepted。

报告绑定已验证原交付的正文 SHA-256、记录 SHA-256、规格 SHA-256、订单和批次。签发时间只获取一次，规则评估与许可日期使用同一 UTC 时间。有效期最多 7 天，accepted 还受许可截止日当天结束约束。拒收报告保留正常有效期，保证拒收决定可以回流。再次检查追加新报告；旧版本保留。

AEGIS 允许保存同交付的多次检查。FORGE 只对当前交付应用一次决定，已应用 review/rejected 后需新交付再处理，这一约定避免历史报告无序覆盖。

## 规模与信任边界

扫描平均时间 O(N × F)，空间 O(N)，原生 JSON 入内存，最多 5000 行 / 8 MiB。原型不提供流式大文件、外部附件验证、身份认证、报告撤销或防管理员篡改。
