# HELIX：AI4Science 数据飞轮详细介绍书

版本 0.1 · 可运行理论态 · 2026-11

## 1. 项目要解决什么

开放科学数据散落在论文仓库、代码仓库、实验数据库、图像集合、三维模型库和视频资源中。单纯把这些内容下载下来，得到的是资产库；只有把资产转换成有证据、可验证、可评测的任务，再依据模型弱项调整下一轮数据，才形成数据飞轮。

HELIX 的目标是建立这个可追溯闭环：每条训练样本都能回答“从哪里来、经过什么变换、为何认为答案正确、能否用于训练、下一轮为什么继续采它”。

理论态不是空页面。这个版本把最小闭环实现为可运行代码，同时明确把大规模科研生产需要的能力列为扩展路线。它适合用于开源展示、架构讨论、课程演示、数据工程验证和后续研发起点。

### 1.1 三个层次

| 层次 | 定义 | 本版本状态 |
| --- | --- | --- |
| 理论与策略 | 学科归类、内容构造、独立验证、奖励与反馈 | 完整说明与设计配置 |
| 可执行基线 | 原始资产保存、结构化提取、任务生成、导出、反馈 | 已实现，可本机运行 |
| 科研生产系统 | 大规模多模态理解、专家审核平台、分布式产线、真实训练实验 | 后续扩展，不声称已完成 |

### 1.2 核心判断

飞轮的价值应当用“独立评测上的能力改善 / 获取数据的总成本”衡量。数据量增加、题干变长、术语变难、模型自己给自己高分，都不能替代这个指标。

本项目没有训练收益实验，因此不提供虚构的提升曲线或科研正确率。页面数字由 SQLite 的实际记录计算。外部模型、专家和训练器都属于显式接入组件。

## 2. 总体架构

```text
开放来源 / 本地清单
        │
        ▼
许可记录 → 原文件对象存储 → 来源家族 / 内容指纹
        │
        ▼
多模态解析 → 学科—子学科—知识点 → 证据对象
        │
        ▼
构造 QA / 研究流程 / 研究方案 / 可验证任务
        │
        ▼
来源许可 → 证据完整性 → 结构一致性 → 独立验证 → 基准隔离
        │                                     │
        ▼                                     ▼
RL / SFT / DPO JSONL                      审核 / 隔离区
        │
        ▼
外部模型训练和评测 → 错误分类 → 下一轮处理优先级
```

后端采用 Python 标准库，数据目录包含 SQLite 数据库和以 SHA-256 命名的对象文件。前端与 API 同源，不需要构建工具。数值任务 ID 来自“资产、操作、生成器、算法版本”，重复运行不会重复创建同一任务。

后台作业用于网络检索和模型调用，界面通过作业状态显示完成或失败。单个服务进程同时只执行一个此类作业。资产、任务、运行和反馈保存在数据库中；作业通知为内存状态，重启会丢失通知，已落库内容保留。

### 2.1 为什么先做小而完整的闭环

图片理解、复杂 CAD 约束、化学机理与医学推理需要不同的验证器。一个通用模型给所有任务打分，很容易把错误题目和错误答案同时收进训练集。先在可独立复算的任务上验证数据契约、分流、导出和反馈，再逐步接入学科验证器，可以把理论变为可检查的软件行为。

## 3. 开放来源与多模态资产

### 3.1 来源策略

“网站可访问”“论文开放获取”“数据可训练”“允许再分发”是不同条件。每条资产必须保留自己的许可和来源；不能只给整个网站贴一个开源标签。

v0.1 实现 arXiv 和 Crossref 的官方 API 元数据检索，单次最多 20 条，默认 5 条。arXiv 保存标题、摘要和论文标识；Crossref 保存 DOI 和可用描述。连接器将许可标记为 unknown，等待逐条核验。返回的许可链接只能作为核验候选，不能直接证明全文或附件的复用条件。

其他网站通过 JSON Manifest 接入。Manifest 可以带本地文件路径或 HTTPS 下载链接。下载器校验允许的来源主机、公开地址、HTTPS 和每次重定向，并限制每文件 50 MB。对生产环境仍应使用独立网络出口策略，应用层 DNS 检查不能作为网络隔离的全部保障。

### 3.2 资产类型矩阵

| 模态 | 常见原始格式 | 可构造任务 | v0.1 / 后续能力 |
| --- | --- | --- | --- |
| 论文文本 | PDF、XML、TeX、Markdown | 证据 QA、方法复现、研究综述 | 元数据与文本归档；PDF 全文解析待接入 |
| 科研图像 | PNG、TIFF、SVG | 图表解释、数值读取、条件反推 | 原文件归档；OCR/VLM/图表校准待接入 |
| 实验视频 | MP4、WebM | 事件排序、过程状态、轨迹推断 | 原文件归档；帧提取和时序定位待接入 |
| CAD 与几何 | STEP、STL、OBJ | 尺寸约束、拓扑、制造与仿真 | ASCII STL 面片面积解析；STEP 内核待接入 |
| 分子与晶体 | XYZ、PDB、CIF、SDF | 结构几何、性质预测、反应验证 | XYZ 距离解析；化学与晶体有效性待接入 |
| 表格与时序 | CSV、Parquet、HDF5 | 统计、动力学、趋势与反演 | CSV 数值列解析；大文件与单位库待接入 |
| 代码与仿真 | Python、Notebook、网格文件 | 补全、调试、科学计算复现 | 文本和文件归档；隔离执行器待接入 |
| 音频与波形 | WAV、FLAC | 频谱、声学事件、实验状态 | 原文件归档；信号处理待接入 |
| 地理遥感 | GeoTIFF、NetCDF、GeoJSON | 时空变化、多圈层关联 | 原文件归档；坐标和栅格解析待接入 |
| 生物序列 | FASTA、FASTQ | 片段统计、变异和功能约束 | FASTA 序列长度；功能验证待接入 |

任何二进制文件都可以先归档，但归档成功不代表已理解内容。默认演示的 10 类模态记录保存的是原创 JSON 观测标注，不是对应的真实图片、视频、CAD 或实验数据。

### 3.3 统一资产协议

```json
{
  "title": "观测记录",
  "source_id": "原始论文或数据集的稳定标识",
  "group_id": "同一来源家族",
  "source_url": "https://source.example/item",
  "modality": "table",
  "license": "CC-BY-4.0",
  "text": "来源文本或规范化事实",
  "facts": {
    "quantity": "pressure",
    "values": [12, 18, 24, 30],
    "unit": "Pa"
  },
  "is_demo": false
}
```

实际入库还记录文本 fingerprint、原文件 object_sha256、split、classification、created_at。自动解析时保留 original_description 和解析器版本，并把事实关联到原始文件哈希。

当前事实协议是一列数值，适用于验证闭环。正式多模态证据应扩展 page、bounding_box、frame_range、atom_indices、mesh_faces、table_cells 等定位字段。不同证据不能只因共享一个 URL 就被视为支持同一结论。

## 4. 分类与数据策略

### 4.1 七个核心方向

默认核心方向为数学、物理、化学、生物、天文、地球科学、工程与计算。金融、医学作为扩展方向。这个七类配置是工程统一口径：原始策略中“七分类”和后续列举的方向数量并不完全一致，因此没有假装原文提供了唯一完整枚举。

每个方向包括学科、子学科和知识点三级路径。v0.1 使用关键词命中与人工 discipline 标签进行排序，返回 Top-3 候选。这里的 retrieval_score 是检索分，不是模型概率，不代表标签已验证。

### 4.2 原策略的分层候选构造

设计版采用三级候选展开：一级 3 个候选，二级 5 个，三级 5 个。可用 beam search 保留 3 条最相关路径，避免组合无限增长。设计配置位于 configs/research_recipe.json，当前基线不会自动执行这份科研级规格。

对经过校准的置信度 p，保留原策略的计分形式：

```text
points(p) = 3, p >= 0.99
            2, 0.95 <= p < 0.99
            1, 0.90 <= p < 0.95
            0, otherwise

path_score = Σ points(p_level)
```

三级学科路径最高 9 分。如另加图像描述置信度，应独立记录为第 4 项，不能混用不同满分。原文画板出现 97%、92% 等档位，工程版按阈值映射，而不是临时添加未定义分值。

这套分数只用于候选排序。模型自报的“99%”不是经过统计验证的正确率。正式使用需要带标注的校准集，检查 reliability curve、ECE 或 Brier score，并按学科分别校准。置信度不应取代来源一致性和答案验证。

### 4.3 六维信息核

每条科研任务应提取六项：学科知识点、研究方向性质、知识点组合、干扰条件、交叉学科方向、结构复杂度。前三项决定任务内容，后三项帮助定义难度与验证方式。

跨学科不是强行换一套术语。把推荐系统的嵌入分布图改称化学实验，再据此推断催化机制，会破坏证据关系。跨领域构造只有在数据重新模拟、假设明确、来源标识完整时才能成立；必须标注为构造场景。

## 5. 内容生成：不止 QA

### 5.1 可执行产物

| 产物 | 内容 | 验证与用途 |
| --- | --- | --- |
| Numeric QA | 观测序列、计算目标、结构化答案 | 独立复算，可导出训练数据 |
| Evidence QA | 问题、答案、可检查说明、证据 | 开放式内容，待审核 |
| Research Workflow | 节点、输入、输出、验证步骤与依赖 | DAG 草稿，待审核 |
| Research Proposal | 研究动机、已有证据、方法、限制 | 研究方案，不冒充已发表论文 |

模板模式完全离线，仅处理明确标注的原创演示资产。模型模式通过标准 Chat Completions JSON 接口工作，生成结果标注模型来源，不会在缺少密钥时暗中使用模板代替。

对于数值 QA，题目由确定性程序基于事实构造，模型负责生成候选答案。模型不会拿到参考答案。对于开放式产物，模型直接基于证据构造内容，但自动流程不会授予“科学正确”状态。

### 5.2 科研级任务路线

原策略关注逆向推断、学科交叉、多层推理、强干扰选项和唯一解。这些要求保存在科研级设计配置中。选择题目标为至少 7 个选项，可检查的解题步骤目标为 6 步；这些是构造约束，不是正确性指标。

建议扩展的任务族包括图表与表格联合推断、实验条件反推、仿真参数识别、CAD 约束求解、数值稳定性诊断、代码复现、分子几何与化学合理性判断、跨论文证据冲突分析。

任务难度应该来自必要的信息整合和科学约束，而不是强制使用冷门定理、添加不相关术语或写更长的解释。对于唯一解要求，应检查题目信息是否足够、假设是否完整、解集是否唯一。无法证明唯一时，转为开放式任务并保留不确定性。

### 5.3 Paper 类产物的界限

HELIX 的 Paper 产物是研究方案草稿。没有实际实验就不产生“实验结果”；没有真实参考文献就不生成虚假引用。论文总结需要实际原文作为证据，不能把仅凭标题生成的文字当成论文内容。

研究方案草稿可以进入人工研究工作流，不能因为语言专业就直接当作模型训练中的真实科学知识。

## 6. 五层质量门槛

五层检查是对原策略“奖励筛选—专家抽检—合格样本—回流”的可执行分解，具体五层名称属于本项目的工程定义。

### 6.1 来源与许可

资产必须具有来源标识和明确许可。当前自动允许 CC0-1.0、CC-BY-4.0、CC-BY-3.0、MIT、Apache-2.0。未知或复杂许可进入隔离。这个白名单是参考工程策略，不是自动法律判断器，尤其需要区分代码许可和数据许可。

### 6.2 证据完整性

数值事实必须与记录的规范化证据一致。自动文件解析会保留原文件哈希和解析版本。手工 Manifest 事实只是提交者的声明；本版本没有证明其与远端论文完全一致，因此正式数据仍需来源抽检。

### 6.3 结构与一致性

检查有效数值、数量与单位，严格限定输出为 JSON。原始策略样例中出现“答案集合包含一个选项，解释又否定该选项”的问题。正式选择题验证器应把选项真值、最终答案集合和逐项解释绑定起来；当前闭环使用数值任务，避免在没有专用逻辑验证器时自动放行选择题。

### 6.4 独立答案验证

基线覆盖 mean、delta、ratio、range。参考答案用 Decimal 复算，候选答案采用严格 JSON answer/unit 契约。相对误差容忍 1e-6，绝对误差容忍 1e-8。NaN、Infinity、布尔值、缺少单位和不匹配单位都不能获得奖励。

生成器的候选通过浮点运算或外部模型产生，验证器独立复算。没有执行模型生成的 Python，也没有拿模型自我评分当事实。自动奖励只验证数值结果与单位，不保证任意自然语言解释正确；目前导出回答只含结构化答案。

### 6.5 基准隔离

先按 group_id 对来源家族划分 train、validation、holdout，再构造任务。同一论文的所有图、视频帧、附件和派生题应共用 group_id。当前默认按哈希桶分配 80/10/10；小数据集不保证精确比例。

显式 benchmark 资产进入 holdout。模型生成和开放式合成不能读取 holdout 资产；演示模板允许产生隔离状态的任务，以检查出口门槛。训练导出只接受 train 或 validation，holdout 永远禁止导出。holdout 评测记录不参与优先级调整。

不能先按题目随机划分，再认为没有泄漏。同一张图的改写、同一论文的不同页、论文的不同版本，都可能泄漏。跨来源近重复、语义重复和翻译重复尚未实现，需要后续建立污染检测索引。

## 7. RL 数据构造与模型训练

### 7.1 RL 数据不等于带答案的 QA

SFT 用目标答案进行监督学习；DPO 使用好坏候选对；在线 RL 需要 prompt、可访问的环境或验证器、奖励规则，以及策略模型实时采样的结果。

本项目导出的 RL 记录包含 prompt、ground_truth、reward_spec 和来源信息。ground_truth 交给奖励函数，不能拼接到模型输入。生成时的候选奖励是离线验证记录，不能替代训练器对新输出重新计算奖励。

```json
{
  "id": "t_...",
  "prompt": [{"role": "user", "content": "仅含题目和必要观测"}],
  "ground_truth": {"answer": 21.0, "unit": "Pa", "rtol": 0.000001, "atol": 0.00000001},
  "reward_spec": "helix.numeric.v1",
  "metadata": {"asset_id": "a_...", "group_id": "...", "split": "train", "is_demo": false}
}
```

### 7.2 奖励函数

```text
R(answer) = 1，数值有限、单位匹配、误差在容忍区间内
            0，其他情况
```

v0.1 不按回答长度、术语密度或格式之外的装饰加分。科研级扩展可以结合约束满足、数值精度、程序正确性、实验复现结果和步骤级检验，但必须防止模型通过格式投机获得奖励。

### 7.3 SFT 与 DPO 导出

SFT 选择至少一个通过独立验证的候选，写为 user/assistant messages。DPO 要求同一任务同时存在通过和失败候选，写为 prompt/chosen/rejected。只有正确候选而没有错误候选时，不会伪造一条真实模型偏好对。

模板演示确实包含程序生成的错误答案，但会明确标记为演示；它适合检验数据接口，不是有代表性的偏好训练分布。模型模式当前每题只采样一个候选，因此往往没有 DPO 对，后续可添加独立多采样。

### 7.4 训练集打包

CLI 导出 JSONL，并生成对应 manifest：行数、格式、split、是否包含演示、SHA-256 和生成时间。默认排除演示数据。若只有演示数据，正式导出应为 0 条，这是预期行为。

可选 examples/train_grpo.py 提供 TRL 对接入口。它需要自行安装 TRL、datasets、适配的模型和 GPU；核心演示不依赖这些库。此入口没有在本项目交付过程中执行模型训练，版本和硬件兼容性需要单独验证。

## 8. 反馈如何驱动下一轮

模型完成评测后，提交 task_id、prediction 和 model。系统用相同的独立奖励函数复算，保存原始输出和奖励。页面可手动提交，CLI 支持 JSONL 批量导入。

对学科 d 的错误率，用指数移动平均更新：

```text
e_d(t) = 0.7 × e_d(t−1) + 0.3 × (1 − reward)
w_d = (1 + 2 × e_d) / Σ_j (1 + 2 × e_j)
```

这个权重提供一个简单、可检查的反馈基线。没有反馈时七个方向权重一致。错误较多的方向在下一次 run 中先处理。权重不修改已存在任务，不能绕过许可和质量门槛。

v0.1 只对已经入库的资产重排，不会自动向网站抓更多数据。正式飞轮需要把“弱项 → 检索主题 → 资产候选 → 任务族 → 训练收益”串起来，并显式设置成本与配额。

### 8.1 建议的生产调度目标

```text
value(x) =
  weakness(domain)
  × evidence_quality(x)
  × verification_probability(x)
  × novelty(x)
  / estimated_cost(x)
```

上式是设计建议，不是已经测得的价值函数。每个因子要有观测依据；冷启动时保留探索配额，避免只采易验证、低成本、热门学科的数据。失败样本也应分类：来源不全、解析失败、题目不适定、模型错误、验证器缺陷，不同原因不能都归咎于模型能力。

## 9. 评测设计与成功标准

数据飞轮应进行多轮可复现消融实验。固定基础模型、训练预算、最终测试集和评测代码，对比随机采样、静态学科配额、弱项驱动采样。保留相同训练 token 预算，避免把更多训练量当成策略优势。

| 维度 | 建议指标 | 本版本是否有结果 |
| --- | --- | --- |
| 数据质量 | 专家抽检正确率、证据覆盖、单位错误、重复率 | 无正式抽检结果 |
| 任务价值 | 难度分布、学科覆盖、题型覆盖、可解性 | 有基线计数，无科研级结论 |
| 模型效果 | 独立任务成功率、学科细分表现、OOD 表现 | 未训练，未测得 |
| 飞轮效率 | 每条通过样本成本、人工分钟数、生成通过率 | 有本地通过计数，成本未接入 |
| 防污染 | 来源家族重叠、语义近重复、最终测试集污染 | 来源家族隔离已实现，其余待扩展 |

对真实科学推理任务，专家一致性和验证器覆盖率比单一 LLM judge 分数更有价值。任何提升都需要报告样本量、置信区间、任务难度以及失败案例。

## 10. 使用指南

### 10.1 启动

```bash
python3 -m helix seed
python3 -m helix run --limit 24
python3 -m helix serve
```

访问 http://127.0.0.1:8765。seed 可重复执行，重复资产不会新增。run 按版本确定任务 ID，重复运行继续处理剩余任务；全部处理完后新增 0 条。

### 10.2 真实元数据接入

```bash
python3 -m helix discover arxiv "computational fluid dynamics" --limit 5
python3 -m helix discover crossref "protein structure" --limit 5
```

检索结果不会直接成为可训练样本：需要许可核验、获得允许使用的内容，以及结构化证据提取。

### 10.3 原文件归档与解析

```bash
python3 -m helix import examples/manifest.json
python3 -m helix import path/to/manifest.json --download
```

local_file 相对 Manifest 所在目录，不能越出该目录。extract 字段支持 csv、fasta、xyz、stl；没有 extract 时只归档，不假装语义解析完成。浏览器导入只写元数据，不允许网页指定任意本机路径读取文件。

CSV 需声明 column 和 unit；ASCII STL 需声明长度 unit；XYZ 可声明长度 unit，默认 angstrom；FASTA 输出 residue 长度。错误记录会在导入结果 errors 中返回，其他合法条目仍可保存。

### 10.4 模型接入

设置 HELIX_MODEL_BASE_URL、HELIX_MODEL 和 HELIX_MODEL_KEY。base URL 必须为 HTTPS，接口需兼容 Chat Completions 与 JSON response_format。具体模型若不支持这些参数，应修改 providers.py 适配，不要把失败当成功。

模型模式仅处理许可明确、非 holdout 的资产。数值任务需要 facts。开放式产物可使用文本，但始终待审核。模型返回超限、格式错误或调用失败都会保留失败状态；不自动回退到演示生成器。

### 10.5 导出

```bash
python3 -m helix export --format rl --split train --output exports/train.rl.jsonl
python3 -m helix export --format rl --include-demo --output exports/demo.rl.jsonl
```

正式训练前检查 manifest、来源许可和数据卡。不要仅根据文件扩展名就认为数据适合训练。

## 11. 扩展路线

### 11.1 多模态解析

PDF：页级提取、图表定位、公式 LaTeX、引用和图注对齐。图像：OCR/VLM 联合解析，保存裁剪区域、坐标和识别不确定性。视频：帧级与片段级证据，禁止用单帧替代整个过程。CAD：引入 Open Cascade 或等价内核，检查几何、拓扑、尺寸与可制造性。

化学：分子合法性、价态、手性、物理量与仿真约束。地理：坐标参考系、时空分辨率、缺失值和重采样来源。代码：无网络隔离容器、CPU/内存/时限、依赖锁定和可重现环境。

### 11.2 多 Agent 分工

可将现有模块扩展成调度 Agent、采集 Agent、学科 Agent、构造 Agent、Verifier Agent 和专家审核入口。Agent 是职责划分；不意味着每个阶段都必须调用模型。验证器应尽量由确定性算法、工具或独立专家承担。

调度器负责预算、配额、幂等与失败恢复；各 Agent 输出统一协议。避免多个 Agent 相互重复引用，把同一错误当作独立证据。

### 11.3 生产工程

建议升级到任务队列、对象存储、PostgreSQL、向量/指纹索引、版本化配置和审计事件。模型调用保留模型版本、提示词哈希、成本和重试信息。审核平台需要有权限的审核者、理由、证据修改记录、版本快照与撤销机制。

当前 SQLite 适合本地理论验证，不代表百万级数据生产吞吐。网页没有登录、多人权限或多租户隔离，不应直接公开部署。

## 12. 开源与许可

仓库公开代码、设计文档、原创演示与通用数据协议。运行数据库、外部抓取内容、密钥、原始内部策略文档和媒体附件不应作为默认开源产物。

代码和文档使用 MIT；原创演示采用 CC0-1.0。每个外部资产保留其独立许可和来源。模型生成产物需要考虑输入来源与服务条款，不能因为由 AI 生成就自动获得统一的开放许可。

项目保留策略的思想和工程化映射，不将内部链接、原始图表、实验表格或私人数据打包进公开仓库。

## 13. 参考与依据

设计启发来自项目发起者的《AI+专业学科与数据飞轮构造增长》策略，包括三级学科归类、档位计分、信息核、难题构造、奖励筛选和专家反馈。该策略是设计来源，不是已经验证的科学效果证据。

- [arXiv API User Manual](https://info.arxiv.org/help/api/user-manual.html)：论文元数据查询协议。
- [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)：DOI 元数据与来源信息。
- [OpenAlex Entity API](https://docs.openalex.org/how-to-use-the-api/get-single-entities)：后续可扩展的学术实体标识方案；本版本没有 OpenAlex 连接器。
- [TRL GRPO Trainer](https://huggingface.co/docs/trl/grpo_trainer)：prompt 与自定义奖励函数的训练接口参考。
- [DeepSeekMath](https://arxiv.org/abs/2402.03300)：GRPO 相关方法出处，不代表本项目复现了论文效果。

外部来源支持各自的协议或方法描述，并不构成对 HELIX 整体有效性的验证。下一阶段最有价值的工作，是选定一个学科、一个可靠验证器和一份严格隔离的评测集，完成真实的单学科闭环实验。
